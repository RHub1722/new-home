# Homealize — мониторинг участков под строительство дома (999.md)

**Дата:** 2026-10-29
**Статус:** дизайн согласован, ожидает ревью спецификации
**Источник требований:** диалог brainstorming + `code_artifact.md` (справочник населённых пунктов в радиусе 30 км от Кишинёва)

## 1. Цель

Программа, которая несколько раз в день собирает с 999.md объявления о продаже участков под строительство, оценивает каждый участок по взвешенной модели («весы») и показывает лучшие варианты: уведомлениями в Telegram, в веб-дашборде с картой и в Excel-файле.

Участок нужен **для строительства дома для себя**, поэтому модель оценки ставит комфорт жизни (дорога, инфраструктура, коммуникации) рядом с выгодностью цены.

### Критерии успеха

- Прогоны идут по расписанию без ручного вмешательства; при сбое тех. тревога приходит в Telegram в рамках того же прогона.
- Новое подходящее объявление приходит в Telegram не позже ближайшего прогона (≤3 ч в дневные часы).
- Каждый балл объясним: разбивка по компонентам видна в боте, дашборде и Excel.
- Прогон без новых объявлений занимает меньше 2 минут.

## 2. Требования

### Жёсткие фильтры (объявление не попадает в топ и уведомления)

| Фильтр | Значение |
|---|---|
| Тип предложения | «Продам» |
| Тип участка | только «Участок под строительство» (не «под с/х», не садовый) |
| Площадь | от 5 до 10 соток включительно |
| Удалённость | ≤30 км по дорогам до ближайшего въезда в Кишинёв |
| Бюджет | цена ≤50 000 € |

Бюджет отсекает только топ и уведомления. Для расчёта рыночных медиан используются **все** подходящие по остальным фильтрам участки, включая дороже бюджета.

### Мягкие требования (влияют только на балл и метки)

- Отсутствие электричества, газа, воды, канализации **не исключает** участок. Такой участок получает метку, например «⚠ нет электричества (не указано в объявлении)», и меньший балл за коммуникации.
- Объявления агентств не исключаются, в карточке показывается тип автора.

### Вне объёма v1

- Другие сайты (makler.md и т. п.): интерфейс адаптера источника это позволяет, но в v1 только 999.md.
- Синхронизация с Google Sheets (v1 даёт .xlsx, который можно открыть в Sheets вручную).
- Проверка участка по кадастру, ML-прогноз цены, анализ фотографий.

## 3. Что известно о 999.md (разведка 2026-10-28)

### Поиск объявлений

Страница списка `https://999.md/ru/list/real-estate/land?...` **не содержит объявлений в исходном HTML**: их подгружает фронтенд через `POST https://999.md/graphql`, операция `SearchAds`.

Переменные запроса для наших фильтров:

```json
{
  "input": {
    "source": "AD_SOURCE_DESKTOP_REDESIGN",
    "sort": "SORT_ADS_DATE_DESC",
    "pagination": {"limit": 78, "skip": 0},
    "subCategoryId": 1407,
    "filters": [
      {"filterId": 16,   "features": [{"featureId": 1,   "optionIds": [776]}]},
      {"filterId": 42,   "features": [{"featureId": 258, "optionIds": [1039]}]},
      {"filterId": 1211, "features": [{"featureId": 245, "range": {"min": "5", "max": "10"}, "unit": "UNIT_ARE"}]}
    ]
  },
  "includeAddress": true,
  "locale": "ru_RU"
}
```

- `16/1/776` означает «Продам», `42/258/1039` «под строительство», `1211/245` площадь в сотках (`UNIT_ARE`).
- Ответ: `searchAds { ads [...] count }`. У каждого объявления есть `id`, `title`, цена и фото (фрагмент `PriceAndImages`), адрес (при `includeAddress: true`), `state`, `isExpired` и `reseted` (дата обновления). Точные имена вложенных полей фиксируются по реальному ответу, сохранённому как фикстура. На 2026-10-28 `count` ≈ 1 775 по всей Молдове.
- Продвигаемые объявления (на 13–14 соток, «под с/х» и т. п.) приходят **отдельными** операциями `BoostersRandomChunks`. Через `SearchAds` выдача чистая.
- Полный текст GraphQL-запроса снимается из браузера при реализации и хранится в адаптере как константа.

### Карточка объявления

`https://999.md/ru/<id>` отдаёт все данные в исходном HTML (JS не нужен):

- **JSON-LD** (`script[type="application/ld+json"]`, `@type: Product`): название, описание, фото, `offers.price`, `offers.priceCurrency`.
- **Характеристики:** «Тип участка», «Площадь земли» («6 сотки»), «Автор объявления» («Частное лицо» / агентство).
- **Дополнительно:** «Газопровод», «Электроснабжение», «Водоснабжение», «Канализация», «Расположен в населенном пункте», «Рядом с лесом» (присутствие пункта = есть).
- **Адрес:** строка вида «Кишинёв мун., Гратиешты, Окраина, -, -».
- **Координаты:** в ссылке «Показать на карте», параметры `map_lat=47.09921&map_lon=28.8165`.
- «Обновлено», «Просмотры», «Тип предложения».

### robots.txt

`User-agent: *` не запрещает `/ru/list/...`, `/ru/<id>` и `/graphql`. Запрещены `/api/`, ссылки с `clickToken`, `placement`, `adType`, `location` и т. п.: их не используем. У сайта есть страница лимита запросов (`999.md_request_limit.html`).

## 4. Архитектура

Один Python-пакет `homealize`. Каждый модуль делает одно дело и общается с остальными через типизированные модели (pydantic/dataclasses).

```
config/settings.yaml        фильтры, веса, пороги, расписание, точки въезда
.env                        TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID (в .gitignore)
data/settlements.yaml       справочник сёл из code_artifact.md
data/homealize.db           SQLite
exports/                    latest.xlsx + homealize_YYYY-MM-DD.xlsx
src/homealize/
  sources/base.py           интерфейс источника: search() -> [ListingStub], fetch(id) -> ListingDetail
  sources/nine99/           адаптер 999.md: search.py (GraphQL), ad_page.py (HTML), http.py (вежливый клиент)
  enrich/routing.py         км и минуты до ближайшего въезда (OSRM table API)
  enrich/poi.py             загрузка POI из Overpass + расстояния до ближайших
  enrich/settlement.py      привязка объявления к селу (ru/ro/транслит)
  enrich/currency.py        курс MDL→EUR от BNM
  scoring/                  компоненты балла, медианы, итог, метки
  storage/                  SQLite, нумерованные SQL-миграции, репозитории
  notify/telegram.py        уведомления, дайджест, команды бота
  export/excel.py           .xlsx
  dashboard/app.py          Streamlit
  pipeline.py               один прогон целиком
  scheduler.py              расписание (APScheduler)
  cli.py                    точка входа
tests/
  fixtures/                 сохранённые ответы SearchAds (JSON) и HTML карточек
docker/                     Dockerfile, docker-compose.yml, Caddyfile (этап 5)
```

### Команды CLI

| Команда | Что делает |
|---|---|
| `homealize init-db` | создаёт или мигрирует базу, загружает `settlements.yaml` |
| `homealize refresh-poi` | скачивает POI и места (`place=*`) из Overpass |
| `homealize run [--dry-run]` | один прогон; `--dry-run` не шлёт уведомления |
| `homealize rescore` | пересчёт баллов без обращения к сайту |
| `homealize export` | пересобирает .xlsx |
| `homealize serve` | планировщик + Telegram-бот в одном процессе |
| `homealize dashboard` | запускает Streamlit |

### Поток одного прогона

1. **Сбор.** Полный проход `SearchAds` страницами по 78 (≈23 запроса).
2. **Предфильтр по региону.** По адресу из результатов поиска оставляем мун. Кишинёв и районы Яловень, Страшень, Анений Ной, Криулень, Хынчешть, Орхей. Объявления без адреса пропускаем дальше.
3. **Сравнение с базой.** Новые, изменилась цена, изменилась дата обновления (`reseted`), пропавшие.
4. **Детали.** Загрузка карточек только для новых и изменившихся.
5. **Фильтр.** Тип участка и площадь по данным карточки; удалённость после маршрутизации. Не прошедшие получают статус `filtered_out` с причиной.
6. **Обогащение.** Курс валюты, село, маршрут, инфраструктура.
7. **Дубликаты.** Группировка (см. §5).
8. **Оценка.** Пересчёт балла у **всех** активных объявлений (медианы меняются).
9. **Снятые.** Объявление, которого нет в двух полных проходах подряд, получает статус `removed`. Счётчик `missed_scans` растёт, только если проход поиска завершился полностью: оборванный проход ничего не снимает.
10. **Уведомления и экспорт.**

Данные карточек и история цен сохраняются по мере загрузки (повторная загрузка идемпотентна), поэтому долгий первый прогон не держит транзакцию открытой. Шаги 7–9 выполняются одной транзакцией. SQLite работает в режиме WAL, чтобы дашборд читал базу во время прогона.

### Расписание (Europe/Chisinau)

- Прогоны в 07:00, 10:00, 13:00, 16:00, 19:00, 22:00.
- Дайджест в 20:00.
- POI из Overpass обновляются раз в месяц.
- Курс BNM кэшируется на день.

Все времена задаются в `settings.yaml`.

### Первый запуск

Карточки загружаются для всех объявлений региона (≈500–800 штук, 30–40 минут один раз). Уведомления о «новых» на первом прогоне не отправляются, только сводка «загружено N участков, топ-10: …».

### Правила данных

- **Валюта.** Цены в MDL переводятся в EUR по официальному курсу BNM на дату прогона. Все сравнения ведутся в EUR.
- **Дубликаты.** Объявления с координатами в пределах 50 м, одинаковой площадью и разницей цены ≤10% получают общий `duplicate_group_id`. Дашборд показывает группу одной строкой с минимальной ценой («ещё N объявлений»), уведомление по группе отправляется один раз.
- **Приблизительные координаты.** Если в карточке нет координат, берётся центр села (из `settlements` или OSM `place=*`) и ставится `coords_approx = true`.
- **Привязка к селу.** Название из адреса сравнивается с `name_ru`, `name_ro` и `aliases` после нормализации (регистр, диакритика ă/â/î/ș/ț, транслит). Неизвестное село добавляется автоматически (`from_document = false`, координаты из OSM `place=*`).
- **Персональные данные.** Телефоны, имена и ники продавцов не собираются и не хранятся. Хранится только ссылка на объявление и тип автора.

## 6. Модель оценки

Итог = Σ (вес × компонент), шкала 0–100. Веса и пороги лежат в `settings.yaml`. Стартовый профиль «сбалансированный»:

| Компонент | Вес |
|---|---|
| Выгодность цены | 0.30 |
| Дорога до Кишинёва | 0.20 |
| Инфраструктура рядом | 0.20 |
| Коммуникации на участке | 0.20 |
| Рейтинг села | 0.10 |

### 6.1 Выгодность цены

- `ppс = price_eur / area_sot` (€/сотку).
- **Выборка для медианы:** объявления со статусом `active` или снятые не раньше 90 дней назад, прошедшие фильтры типа, площади и удалённости (бюджет не учитывается), без метки «подозрительно дёшево», одно на группу дубликатов.
- **Медиана по уровням (первый подходящий):**
  1. то же село, n ≥ 5;
  2. участки с `route_km` в пределах ±3 км, n ≥ 8;
  3. весь регион.

  Использованный уровень и медиана сохраняются в `scores`.
- **Отклонение** `d = (ppс − median) / median`, компонент = `clamp(50 − 125·d, 0, 100)`. Цена на уровне рынка даёт 50, на 40% дешевле даёт 100, на 40% дороже даёт 0.
- **Подозрительно дёшево:** `ppс < 0.25 · median` даёт метку `suspicious_price` («🔍 проверить вручную»). Компонент цены = 50, объявление не попадает в топ и уведомления, но видно в дашборде с фильтром «показать подозрительные».

### 6.2 Дорога до Кишинёва

- Маршрут на машине (OSRM) от участка до каждой **точки въезда**, берётся минимум по времени. Сохраняются км, минуты и название точки.
- Компонент: `m ≤ 5 мин` даёт 100, `m ≥ 30 мин` даёт 0, между ними линейно.
- Участки в черте самого Кишинёва (секторы): `m = 0`.
- Жёсткий фильтр: `route_km ≤ 30`.

**Точки въезда.** Место, где дорога пересекает черту города; координаты задаются в `settings.yaml` и сверяются с OSM при реализации:

1. Север: трасса M2 / Calea Orheiului (Ставчены, Криково, Магдачешты, Пересечино).
2. Северо-восток: Полтавское шоссе / Чеканы (Вадул-луй-Водэ, Бубуечь).
3. Восток: str. Muncești (Бачой, Бубуечь).
4. Юго-восток: bd. Dacia, аэропорт (Сынжера, Ревака, Анений Ной).
5. Юг: Хынчештское шоссе (Костешты, Хынчешть).
6. Юг: трасса на Яловены, Телецентр (Яловены, Резены).
7. Запад: Дурлешты, Буюканы (Дурлешты, Трушены, Думбрава).
8. Северо-запад: Calea Ieșilor, R1 (Гидигич, Ватра, Страшены).

**OSRM.** На этапах 1–4 используется публичный сервер `router.project-osrm.org` с кэшем `route_cache` и паузой ≥1 с между запросами (новых точек 10–40 в день). На VPS (этап 5) поднимается свой контейнер OSRM с выгрузкой Молдовы (Geofabrik); URL задаётся в настройках.

### 6.3 Инфраструктура рядом

- POI загружаются раз в месяц одним запросом Overpass API по области радиусом 35 км от центра Кишинёва.
- Для каждой категории считается расстояние по прямой до ближайшего объекта. Балл категории: ≤500 м даёт 1, ≥1500 м даёт 0, между ними линейно. Компонент = 100 · Σ(вес категории × балл категории).

| Категория | OSM-теги | Вес |
|---|---|---|
| Сетевой супермаркет | `shop=supermarket` или `brand`/`name` из списка сетей (Linella, Kaufland, Fidesco, Local, Green Hills, Nr.1, Velmart) | 0.30 |
| Школа | `amenity=school` | 0.20 |
| Детский сад | `amenity=kindergarten` | 0.15 |
| Аптека | `amenity=pharmacy` | 0.15 |
| Остановка | `highway=bus_stop`, `public_transport=platform` | 0.10 |
| Медпункт | `amenity=clinic`, `amenity=doctors`, `amenity=hospital` | 0.10 |

Список сетей задаётся в `settings.yaml`.

### 6.4 Коммуникации

Электричество 35, газ 30, вода 25, канализация 10 (сумма 100). Отсутствие пункта в «Дополнительно» = 0 по этой позиции и метка `no_<utility>` («⚠ нет газа (не указано в объявлении)»).

### 6.5 Рейтинг села

`potential_score` из справочника (§5); сёла вне документа получают 50 и метку «не изучено».

### 6.6 Объяснимость

Каждый компонент хранит короткое пояснение, которое показывается везде, например: «Цена 82: на 25% дешевле медианы Сынжеры (4 200 €/сот., по 11 объявлениям)», «Дорога 76: 11 мин до въезда bd. Dacia (9,4 км)», «Инфраструктура 64: Linella 380 м, школа 900 м, аптека 450 м, остановки нет в 1,5 км».

### 6.7 Рейтинг

Ранжируются активные объявления, прошедшие все жёсткие фильтры, без меток `suspicious_price` и `hidden`, по одному на группу дубликатов. Сортировка по `total` по убыванию.

## 7. Выходы

### 7.1 Telegram

- Бота создаёт пользователь через @BotFather. Токен и chat_id лежат в `.env`. Бот отвечает только на сообщения из `TELEGRAM_CHAT_ID`.
- **🆕 Новый участок:** впервые увиденное объявление (группа), которое прошло все фильтры, без метки «подозрительно» и не скрыто, с `total ≥ 70` или `rank ≤ 10`. Сообщение: первое фото, село, сотки, цена, €/сотку и отклонение от медианы, минуты до города, метки, разбивка балла, ссылки на 999 и на карту (OSM).
- **📉 Снижение цены:** цена снизилась на ≥5% относительно предыдущей, `total ≥ 60` после снижения. Формат: «было 42 000 €, стало 38 500 € (−8%)».
- **📋 Дайджест (20:00):** число новых за сутки, текущий топ-10 с изменениями позиций, кто выпал из топа (снят, подорожал, скрыт).
- **🛠 Тех. тревога:** исключение в прогоне; `SearchAds.count == 0`; не удалось разобрать >20% загруженных карточек; страница лимита запросов. Повторная тревога того же типа приходит не чаще раза в 6 часов.
- **Команды:** `/top [N]` (по умолчанию 10), `/new` (за 24 ч), `/ad <id>`, `/fav <id>`, `/hide <id>`, `/unhide <id>`, `/status` (последний прогон из `runs`).
- Пороги 70, 10, 5%, 60 задаются в `settings.yaml`.

### 7.2 Дашборд (Streamlit)

- **Топ:** таблица (село, сотки, цена, €/сот., отклонение от медианы, минуты, метки, балл, ★). Фильтры: цена, площадь, максимум минут, обязательные коммуникации, сёла, «показать скрытые», «показать подозрительные», «показать выше бюджета».
- **Карта** (pydeck): точки окрашены по баллу, отмечены точки въезда. По клику открывается карточка.
- **Карточка:** фото, разбивка балла с пояснениями, график `price_history`, ближайшие POI, ссылка на 999, кнопки ★ и «скрыть» (пишут в `user_marks`).
- **Рынок:** медиана €/сотку по сёлам (n ≥ 3) и её динамика по неделям.
- Локально: `http://localhost:8501`. На VPS: за Caddy с basic auth и HTTPS.

## 8. Надёжность и бережность к сайту

- **HTTP-клиент:** один запрос за раз, пауза 2–3 с со случайным разбросом, заголовки обычного браузера (`User-Agent`, `Accept-Language: ru`), таймаут 30 с.
- **Повторы:** на 429/5xx/таймаут до 3 повторов с экспоненциальной паузой (5, 15, 45 с). Если увидели страницу лимита запросов, прогон останавливается и уходит тех. тревога.
- **Валидация:** ответы `SearchAds` проверяются pydantic-моделями. Несовпадение схемы считается ошибкой прогона, а не «0 объявлений».
- **Разбор карточек:** ошибка разбора одной карточки не валит прогон. Объявление остаётся со старыми данными, ошибка пишется в `runs.errors`. Порог 20% вызывает тревогу.
- **Логи:** файл с ротацией (`logs/homealize.log`, 10 МБ × 5).
- **Секреты:** только в `.env`; `.env`, `data/*.db`, `exports/`, `logs/` в `.gitignore`.
- **Overpass, OSRM, BNM:** при недоступности используются последние кэшированные данные, прогон продолжается, в `runs.errors` пишется предупреждение.
